## pipeline
Sources: repo files dated 2026-11-21/22. The compiled functions/lib/meal.js (2026-11-22 13:55) matches the source. The scan is Debug-only for now: AIService.isLive is true only in DEBUG until the privacy go-live.

APP TO SERVER: MealScanSheet.read() (/Users/sammanhcuong/Developer/GymWorkout/GymWorkout/Features/Food/MealScan.swift:550) calls AIService.scanMeal(photo, note:) (/Users/sammanhcuong/Developer/GymWorkout/GymWorkout/Services/AI/AIService.swift:253). That function:
- checks the meal consent (UserDefaults "ai.consent.meal.v1");
- redraws the photo at no more than 1280 px on the long side as JPEG quality 0.8 in base64, which drops EXIF and location;
- calls the Firebase callable scanMeal (asia-southeast1, 100 s client timeout) with MealRequest {image, note? (optional free text), locale "en"/"vi" (the app's language), timeZone}.
premiumCall retries once after an entitlement sync if the server says "not premium" or reports an out-of-date Premium limit.

SERVER: scanMeal is in /Users/sammanhcuong/Developer/GymWorkout/functions/src/meal.ts:105.
1. requireMember checks Auth, App Check (only if enforced), config/ai.mealEnabled, and a verified plan or a tester entry. Pro gets 20 scans a day, Premium 0.
2. image() accepts a JPEG/PNG up to 4 MB, and the note is cut to 200 chars.
3. take() reserves one unit in usage/{purchase}/meal/{member's local day}.
4. One OpenAI Responses call:
   - Model: config/ai.mealModel (default gpt-6.1-terra).
   - Developer message: mealInstructions(locale), 8 lines, about 1,400 chars (about 350 tokens). It asks for up to 12 foods, each with a name, an everyday portion, edible grams and kcal/P/F/C. It says to judge size from plates, cutlery, hands and packaging; to include oil, butter and sauces that are visible or standard for the dish; to use USDA FoodData Central and typical Vietnamese home or street-food versions; and to keep kcal within about 10% of 4/4/9 (alcohol 7). It also asks for a title, a confidence and a one-sentence note, sets isFood false when there is no food, lets the member's note override the photo but never act as instructions, and puts the language line last.
   - User message: input_text "Member's note: ..." or "Estimate this meal.", plus input_image as a data URL with detail "high".
   - Settings: strict json_schema "meal"; max_output_tokens 4000 (reasoning included); store:false; safety_identifier is the hashed uid; reasoning.effort is config mealReasoning (default "low"); 70 s timeout; no retries.
   - Not used: tools, few-shot examples, reference data, prompt_cache_key.
   - Nothing is cached today: the roughly 350-token developer prefix is below OpenAI's 1,024-token caching minimum (OpenAI docs, 2024-25; check whether terra differs).

WHAT COMES BACK:
- A refusal or content_filter becomes isFood:false, and the scan still counts.
- A cut-off or unreadable answer becomes an error. settle() gives the unit back when OpenAI billed nothing; otherwise at most 3 refunds a day.
- Otherwise shapeMeal() returns {isFood, title (max 80 chars), items (max 12) [{name (80), portion (60), grams (≤3000), kcal (≤5000), proteinG and fatG (≤400 each), carbsG (≤800)}], total, confidence (high/medium/low, default medium), note (200), remainingToday}. All numbers are rounded integers, and items without a name are dropped.
- The server does not check that kcal matches the macros.
- Cloud Logging keeps only the uid, model, status and token usage.
- The app decodes MealScan/MealScanItem (AIService.swift:115-144) and maps errors to AIServiceError.

TODAY'S TEST: The model's per-100 g values match USDA (values from memory, not looked up): the egg at 100 g / 143 kcal is USDA's raw whole egg, and the apple at 180 g / 94 kcal is 52 kcal per 100 g. So looking up nutrients for single foods already works. The errors come from the grams and the cooking method: a hard-boiled egg is about 155 kcal per 100 g and a fried egg about 196.

## editing
The review step is in /Users/sammanhcuong/Developer/GymWorkout/GymWorkout/Features/Food/MealScan.swift: `review` at line 411, MealItemRow at 625-666.

What the member can do:
- Edit the meal name (a text field).
- Read a confidence line ("AI estimate · low confidence, check the portions"), the model's note, and "Estimates from a photo can be off by 20% or more".
- Each item row shows the name (read-only) and "portion ×scale · grams · kcal".
- A stepper goes from ×0.25 to ×3 in steps of 0.25. It scales grams, kcal, protein, fat and carbs together, in proportion, so kcal and macros do rescale. The total line (kcal and P/F/C) is recomputed on the phone; the server's total is not used.
- A minus button removes an item.
- Per-item macros are not shown, only the meal's total.

What the member cannot do:
- type exact grams;
- rename or swap a food;
- change the cooking method (fried to boiled);
- add a missed item, such as oil or a sauce;
- edit macros;
- scale outside ×0.25 to ×3, or in finer steps.

Notes:
- The note can only be added before reading. Once a photo is picked, an optional field shows "Add a note (optional), e.g. “fried in butter”" (line 398). The server cuts it to 200 chars, and the prompt says it overrides the photo.
- There is no re-scan from the review. The only way is Cancel and a new scan, which costs another unit.
- After a failed read, "Try again" goes back to the photo screen with the photo and note kept, so the note can be edited and the meal read again. "No food found" clears the photo.

After logging, a meal cannot be edited, only deleted: context menu on Today, or swipe in the quick log.

The scan sheet and meal consent strings have no Vietnamese translation yet. Food names still come back in Vietnamese when the app runs in Vietnamese.

WHAT IS DROPPED: the portion text ("1 bowl"), the original unscaled estimate, the chosen scale, removed items, the confidence, the model's note, the member's note, the photo and the model id. So corrections are kept nowhere, and a saved meal does not show which numbers the AI gave and which the member changed.

ON THE SERVER: only the usage counter usage/{usageKey}/meal/{day} {count, refunds, updatedAt, expireAt (TTL about 2 days)} and a log line with token counts. Firestore rules refuse all client access, and there is no meal collection. The OpenAI call uses store:false; the consent copy says OpenAI may keep inputs up to 30 days for abuse checks.

RISK WHEN ADDING SAVED FIELDS: MealEntry uses Swift's synthesized Codable, which ignores default values. I confirmed this with a 3-line Swift test: a missing key that has a default still throws keyNotFound. If the key is missing, DailyStore.load() (line 485) fails and moves daily.json aside as daily.corrupt-<time>.json, so water, weights and meals then show as empty. Any new field must be Optional.
The existing non-optional MealEntry.source seems to have been added with typed meals on 2026-11-22. It already carries this risk for any daily.json holding a meal saved by an earlier build. That can only affect Debug builds, since the scan is Debug-only.
