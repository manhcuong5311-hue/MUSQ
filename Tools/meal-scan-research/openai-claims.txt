- Data format and example counts:
- Training data is JSONL in the Chat Completions messages format, at least 10 lines.
- Vision examples put images in image_url content parts, as HTTP URLs or base64 data URLs.
- The minimum is 10 examples; OpenAI typically sees gains from 50-100 and recommends starting with 50 good examples, then evaluating. [stated] https://developers.openai.com/api/docs/guides/supervised-fine-tuning (Undated guide, accessed 2026-11-22)
- Image limits for vision fine-tuning:
- At most 50,000 image-containing examples, 10 images per example and 10 MB per image.
- JPEG, PNG or WEBP, in RGB or RGBA mode; no images in assistant messages.
- Images showing people, faces, children or CAPTCHAs are excluded from training.
- Setting detail to low cuts training cost (85 tokens per image on gpt-4o).
- After training, a 13-category safety check can block the model from deployment. [stated] https://developers.openai.com/api/docs/guides/vision-fine-tuning (Undated guide, accessed 2026-11-22)

- Prompt caching for Terra (GPT-5.6-and-later rules) is on by default:
- The default `prompt_cache_options.mode` is 'implicit': one breakpoint at the end of the latest eligible message (a user message, the last tool response, or the last developer message of the opening developer block).
- 'explicit' mode uses only `prompt_cache_breakpoint` markers on content blocks; both input_text and input_image accept them. With no markers, nothing is cached.
- Each request can create up to four cache writes. [stated] https://developers.openai.com/api/docs/guides/prompt-caching (Undated guide; explicit controls added with GPT-5.6 on 2026-07-09 (changelog); accessed 2026-11-22)
- For GPT-5.6 and later, a prefix must be at least 1,024 visible input tokens to be cached. Cache reads cost 0.05x the input rate on GPT-6.1 Terra (0.1x on most other models), whichever lifetime is chosen. [stated] https://developers.openai.com/api/docs/guides/prompt-caching#summary-of-model-differences (Undated guide, accessed 2026-11-22)
- Cache lifetime is set with `prompt_cache_options.ttl`:
- '30m' (default): writes cost 1.25x input.
- '12h' (Responses API only): writes cost 2.5x input.
- `prompt_cache_breakpoint.ttl` overrides it for one breakpoint; `prompt_cache_retention` is deprecated.
Terra prices per 1M tokens for prompts up to 272K tokens: input $1, cached input $0.05, 30m write $1.25, 12h write $2.50, output $5. Longer prompts pay 2x input and cache rates and 1.5x output. [stated] https://developers.openai.com/api/docs/guides/prompt-caching#cache-lifetime (12-hour caching launched 2026-10-20 (changelog); pages accessed 2026-11-22)
- How caching is billed:
- A cache write is not an extra fee on top: each input token is billed once, at the uncached, cached or cache-write rate.
- A read refreshes 30-minute coverage to at least 30 minutes after that read.
- The lifetime decides eligibility for cache-read pricing, but does not guarantee the stored cache is physically reused or that latency drops.
- Cached tokens still count toward TPM limits, and caches are not shared across organizations.
- The cache cannot be cleared manually; it holds key/value tensors for at most 24 h and works with ZDR. [stated] https://developers.openai.com/api/docs/guides/prompt-caching (Undated guide, accessed 2026-11-22)
- Image tokens can be part of a cached prefix: the eligible prefix can include conversation content with images, and input_image blocks accept `prompt_cache_breakpoint`. So fixed reference or example images placed before a breakpoint can be cached. [stated] https://developers.openai.com/api/docs/guides/prompt-caching#what-is-the-prompt-cache (Undated, accessed 2026-11-22)
- Documented pitfall: when a fixed developer message is followed by a changing user message, implicit caching writes through the changing part. The next request with different user content then reuses nothing, not even the shared fixed part. The fix is an explicit breakpoint after the fixed content; explicit-only mode also stops the changing part being written (it is billed at the normal input rate, with no write charge). [stated] https://developers.openai.com/api/docs/guides/prompt-caching#a-shared-prefix-is-not-always-a-cached-prefix (Undated guide, accessed 2026-11-22)
- Applied to this app:
- Put the fixed dish, oil and sauce table first, as an input_text block in a developer message, ending with `prompt_cache_breakpoint`. Top-level instructions cannot hold a breakpoint.
- Set `prompt_cache_options.mode` to 'explicit'.
- Keep model, tools, the text.format schema and reasoning.effort identical between calls.
Later scans with different photos then read the table at $0.05/M, and the photo costs $1/M with no write charge. Under the default implicit mode, each scan probably writes the whole prompt (over 1,024 tokens, photo included) at $1.25/M and never reuses it. The measured ~$0.003 per scan fits that: 1,900 x $1.25/M + 132 x $5/M is about $0.0030, against $0.0026 without a write. Verify with `usage.input_tokens_details.cache_write_tokens`. [inferred] https://developers.openai.com/api/docs/guides/prompt-caching#choose-a-caching-mode (Accessed 2026-11-22)
- These settings are part of the cached prefix and must match for reuse: model, tools, parallel_tool_calls, text.format (the JSON schema), reasoning.effort, text.verbosity and context_management. On models before GPT-6.2, including Terra, changing top-level instructions also changes the prefix. [stated] https://developers.openai.com/api/docs/guides/keep-prefix-unchanged (Undated, accessed 2026-11-22)
- Setting `prompt_cache_options.prewarm` to true fills the cache without generating output; it is billed at the write rate. Setting `prompt_cache_options.comparison_response_id` requests cache-miss diagnostics. The usage object reports cached_tokens, cache_write_tokens and the ttl_30m_tokens / ttl_12h_tokens split. [stated] https://developers.openai.com/api/docs/guides/prompt-caching#prewarm-the-cache (Diagnostics GA 2026-09-08 (changelog); accessed 2026-11-22)
- Cost example for Terra: a 10,000-token reference table costs about $0.0005 per scan when read from cache, against about $0.01 uncached. Each 30-minute write costs about $0.0125 and each 12-hour write about $0.025. With at least one scan every 30 minutes the 30m entry keeps refreshing, so 12h mainly pays off across quiet hours (for example, overnight in Vietnam). [inferred] https://developers.openai.com/api/docs/models/gpt-6.1-terra (Accessed 2026-11-22)
- In the Responses API, Terra supports function calling, structured outputs, file_search, image input, prompt caching and the remote MCP tool. Tool calling requires the Responses API. [stated] https://developers.openai.com/api/docs/models/gpt-6.1-terra (Accessed 2026-11-22)
- Function calling takes more than one request:
- The model returns a function_call; your app runs it; you send a second request with the function_call_output; the model then answers or calls more tools.
- With previous_response_id, all earlier input tokens (including the photo) are billed again as input; they can be cache reads.
- Each sequential model or tool call adds waiting time. WebSocket mode with previous_response_id cuts the overhead between turns. [stated] https://developers.openai.com/api/docs/guides/function-calling#the-tool-calling-flow (Undated guides, accessed 2026-11-22)
- Setting strict: true makes function arguments follow the schema exactly. It requires additionalProperties false and every property listed as required (use null for optional fields); Responses tries to convert schemas to strict by default. For Structured Outputs, the first request with a new schema has extra latency; later requests with the same schema do not. [stated] https://developers.openai.com/api/docs/guides/function-calling#strict-mode (Undated guides, accessed 2026-11-22)
- The docs never explicitly state that function tools and a strict text.format json_schema can be combined in one Responses request. However, OpenAI's official Agents SDK sends both (tools, plus text.format json_schema strict named 'final_output') in the same responses.create call, then loops after tool calls. So Terra can likely call your lookup and then answer in your schema, at the cost of a second model request. [inferred] https://github.com/openai/openai-agents-python/blob/main/src/agents/models/openai_responses.py (main branch, fetched 2026-11-22)
- Remote MCP tool:
- If the food lookup is exposed as a remote MCP server, the Responses API itself calls it during the same request (mcp_call output items). Approval can be set to 'never'.
- You pay only for tokens used to import tool definitions and make calls; there is no per-call fee.
- The tool list is fetched on every request unless the mcp_list_tools item is kept in context.
- MCP rate limits: 1,000 RPM (Build) and 2,000 RPM (Launch, Grow).
- Data sent to the MCP server falls under that server's retention policy. [stated] https://developers.openai.com/api/docs/guides/tools-connectors-mcp (Undated guide, accessed 2026-11-22)
- file_search is an OpenAI-hosted tool that searches vector stores (semantic plus keyword) and runs automatically within the same request.
- Pricing: storage is free up to 1 GB, then $0.10/GB/day; $2.50 per 1,000 calls (Responses API); retrieved tokens are billed at model rates.
- Default chunks are 800 tokens with 400 overlap (configurable 100-4,096). max_num_results is 1-50; fewer results cut tokens and latency.
- Supported files include .json, .md, .txt, .pdf and .docx; .csv is not listed. Limits are 512 MB and 5M tokens per file.
- Rate limits: 500 RPM (Build) and 1,000 RPM (Launch, Grow). [stated] https://developers.openai.com/api/docs/guides/tools-file-search (Undated, accessed 2026-11-22)
- For a dish table of a few thousand to tens of thousands of tokens, a cached in-prompt table is cheaper and simpler than file_search. file_search adds $0.0025 per call, about the whole current ~$0.003 scan, plus retrieved chunks (e.g. 5 x 800 tokens, about $0.004 uncached) and an extra retrieval step. Function calling or MCP add a second model pass or a remote hop. Retrieval tools mainly pay off when the table is too large to send every time. [inferred] https://developers.openai.com/api/docs/pricing (Accessed 2026-11-22)

- OpenAI advises treating effort as a tuning knob rather than the main way to fix quality, and suggests trying lower effort for routine extraction or classification while checking accuracy. - Image detail can be low, high, original or auto; auto is the default in both Responses and Chat Completions.
- low is coarse and does not always use fewer tokens than high.
- high is standard high-fidelity.
- original is for large, dense or spatially sensitive images. [stated] https://developers.openai.com/api/docs/guides/images-vision#choose-an-image-detail-level (Undated guide, accessed 2026-11-22)
- How image tokens are counted on patch-based models:
- The image is covered with 32x32-pixel patches: ceil(w/32) x ceil(h/32).
- It is scaled down to the detail level's pixel limit and patch budget, then multiplied by a per-model factor (1.2 for GPT-6 Astra and the GPT-5.6 family).
- An image needing more than 30,000 patches is rejected.
- Up to 1,500 images and 512 MB per request; PNG, JPEG, WEBP or non-animated GIF.
- Image tokens count toward TPM limits. [stated] https://developers.openai.com/api/docs/guides/images-vision#calculating-costs (Undated guide, accessed 2026-11-22)
